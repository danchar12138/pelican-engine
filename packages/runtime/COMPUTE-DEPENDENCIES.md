# Explicit compute dependencies

Ordinary buffer bindings capture their revision and immutable CPU values at dispatch, as before. Parameters and time are also captured then. `after: [task]` adds ordering only; it does not refresh those captures. Duplicate references count once per consumer, including references repeated across `after` and task bindings.

A binding `{ task: predecessor }` adds an implicit dependency and resolves the predecessor's exact successful output immediately before execution. Later tasks or CPU writes to that logical buffer cannot change the earlier result. Input types must match the kernel declaration; input counts can differ because reads use the source bounds. Output type/count validation is unchanged.

Dependencies must name existing earlier unreleased task handles from the same owner. Strict dense plain `after` arrays and plain task wrappers are validated before task IDs, busy buffers, or dependency references are allocated. Malformed, foreign, released, forward, self, and restored handles produce contextual `TC_COMPUTE_DEPENDENCY` errors. Failed/cancelled dependencies with live source buffers are accepted into the queue and deterministically fail their consumers with `TC_COMPUTE_DEPENDENCY_FAILED` before executor submission, candidate discard, or output mutation. Independent FIFO work continues.

Each unfinished consumer owns one reference to each predecessor and one busy reference to each distinct input/output buffer. This includes task-result source buffers while the producer is still pending. `releaseTask` rejects `TC_COMPUTE_TASK_IN_USE` while consumers remain unfinished. Finishing or cancelling releases references exactly once. Cancelling one producer leaves consumers queued to report dependency failure; owner invalidation cancels the whole unfinished chain.

Only successful tasks retain private result descriptors. A descriptor contains immutable execution input data plus the exact owning buffer object, checked against the live generation before use. Neither `task()` nor `tasks()` exposes these descriptors or CPU aliases. A terminal result alone does not pin its buffer: legacy `releaseBuffer` remains available, clears corresponding private result/source references, and leaves task status unchanged. Future task-result bindings reject released/reused sources with `TC_COMPUTE_DEPENDENCY_RESOURCE`; execution checks the source again before submission.

Every flush collects the union of all current buffer revisions and exact successful result revisions held by live task records, deduplicated by key/revision. Multiple revisions of one key remain live. Releasing a terminal task collects immediately when outside a flush; releases during execution defer collection until flush end. Retained tasks intentionally retain their result revisions until task release, source release, or owner invalidation. The executor must preserve multiple revisions of a key when accepting this live set.

Executor replacement (including replacement with the same instance) cancels unfinished work and clears **all** old private result/source descriptors. Buffer handles, committed CPU buffer data, and inspectable task statuses remain available. Old result bindings fail `TC_COMPUTE_DEPENDENCY_RESOURCE`; ordering after an old successful task remains valid. No historical task result can request an unknown revision from the replacement executor. Ordinary bindings can capture the surviving committed CPU data. Late results and rejections from invalidated execution cannot publish output or escape as unhandled rejections.

Idle snapshots still contain only kernel definitions and current buffers, with no tasks or dependency graph. Restore clears tasks, results and references, changes owner identity, and preserves logical render pins. Dispose clears all state. Snapshot/restore still require every task to be terminal first.

Validation: `node node_modules/tsx/dist/cli.mjs --test tests/compute-dependencies.test.ts` covers diamonds/fanout, snapshot capture semantics, exact overwritten revisions, retention/eviction, source/task busy protection, malformed references and arrays, failure/cancellation propagation, continued independent work, replacement, restore, disposal, and late promises. These are injected CPU ownership tests, not WGSL or GPU evidence. Main integration owns consolidated type checking, multi-version executor validation, and the bounded real GPU DAG. No batching, texture scope, platform policy, or dependencies change here.

The existing compute-render owner contract retains revisions 2 and 1 after two successful tasks overwrite one buffer; releasing the first task then collects revision 1.
