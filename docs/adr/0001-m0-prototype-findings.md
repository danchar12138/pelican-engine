# M0 实装结论与架构决策

状态：风险原型已实现，最后验收结果和完整证据以 `evidence/m0/acceptance.json` 为准。本 ADR 不宣称完整首发引擎完成。

## 选择和实装

| 范围 | 当前选择 | 证据和边界 |
| --- | --- | --- |
| 开发工具 | Node 24.15.0、npm 锁文件；Windows 本地启动脚本 | 项目/用户级准备；无 Git、ZIP、本地外部目录均需复测 |
| TS 编译 | TypeScript 6.0.3 经典 Compiler API | 实测 TS 7.0.2 根入口不再提供 createProgram；M0 不依赖其 unstable AST 接口 |
| 程序构建 | Vite 8.3.5 | 编译和发布分别管理 NODE_ENV；关闭定义扫描副作用，生产游戏代码保留 source map |
| 公开契约 | SDK 定义函数、强类型句柄/数据、有限 Graph IR v1 | 普通玩法系统作为 JS 执行；定义只支持明确静态子集，不是任意 TS 求值器 |
| 增量 | 项目级内容哈希缓存 | 成功产物哈希复查；代码/Schema/默认值变更有明确策略；尚无运行态补丁迁移 |
| 图形基础 | Three.js 0.187.0 的 Renderer + WebGPUBackend + StandardNodeLibrary | 直接构造不带 fallback 的后端，未修改上游包；缺 API/adapter/device 分支验证不请求 WebGL |
| 材质/计算图 | float/vec3/time/add/multiply/sin | 材质降到 TSL，compute 降到私有 WGSL 并读回与参考值比较；游戏不访问底层对象 |
| 场景几何 | Three.js 变换/骨骼/Morph 派生三角形 | 父变换、祖先可见性及单独形变验证；当前 CPU 提取/重建后上传 |
| 光追/PT | 私有 WebGPU compute、三角形 BVH、至多 5 跳的简化积分 | 使用真实几何求交；没有硬件 RT 单元调用或成品降噪；非生产 BSDF/MIS |
| 混合模式 | 光栅 + 35% 追踪图像的合成原型 | 只验证双路径共享几何、模式与更新链；不是已经完成材质级混合照明 |
| 光照 | 原型追踪使用第一个 authored light 与环境参数 | 不宣称多灯/复杂材质一致；光栅还包含明确的私有探针灯 |
| 刚体候选 | Rapier 2D/3D compat 0.21.0 WASM | 实际初始化、碰撞、射线、关节、快照和释放；检测软体 API 存在不等于验证了它 |
| 高级模拟参考 | 小规模 CPU XPBD 绳索/布料、四面体软体、WCSPH 流体 | 单个平移球体双向接触、对照和恢复；没有旋转摩擦、自碰撞、模块间通用耦合和流体表面 |
| 世界参考 | 有限高度分块 + 事务提交 + 碰撞高度/CPU 网格路径 | 异步旧结果作废、共享边界修改、消费者版本一致与恢复；不是完整地形/NavMesh系统 |
| 浏览器验收 | Playwright 1.64.1，有界面真实硬件 WebGPU | 明确检查非 fallback adapter 和后端，不以 hosted CI 证明 GPU 通过 |
| 发布 | dist 静态目录 + 源码 ZIP + 证据 + SHA-256 | 默认剔除开发控制；普通服务器子路径验证；M0 使用 prerelease |

## 资源和状态所有权

M0 以明确的小型 Map/组件状态和受控固定步代替提前开发完整 ECS。句柄、系统权限、结构命令缓冲和生产调度器留待 M1 实现，不将当前 facade 宣称成熟 ECS。

组件与变换快照深拷贝；模拟和世界分别验证捕获恢复。PT 累积是派生历史，几何或相机变动时重置，恢复后重新采样，不保存显卡内部对象。真实 GPU 计时仅覆盖 tracer compute；CPU BVH 构建、上传和 GPU fence 墙钟时间另外报告。

初始动态 tracing 每步全量重建并上传，目的是验证正确性和测量成本。生产实现需要探索 refit、持久缓冲、部分上传、GPU 数据共享和更好的求交布局；不能把原型平均时间当作优化已经完成。

## 性能结论如何使用

本机记录的是 RTX 5070 Ti Laptop、12 GB 级显存和 Ryzen 9 9955HX；它不是已经覆盖所有主流独显的基线集合。原生 1080p 的三模式分别测量，负载是合成小场景。报告保留样本数量、配置、三角形数、BVH/上传时间、compute timestamp 和串行等待墙钟时间。

这些结果不等于持续呈现 FPS，不足以证明完整高质量游戏的 1080p60。PT 简化原型如未达到 16.67 ms 会如实报告，不能降低分辨率、偷切模式或删除光追能力后宣称达标。

M0 的质量门禁是关键技术链路有实际成功和失败证据；M3/M7 才依据具有代表性的资产、复杂度、动态质量和稳定性继续达成完整目标。M0 通过不改变 D04、D22、D23。

## 发现并修复的集成缺陷

- Vite 编译污染进程 NODE_ENV，导致后续开发服务器的控制通道消失；通过环境恢复和并发编译回归修复。
- 发布打包继承 development 环境，可能保留开发 hook；发布构建显式 production 并复测。
- 动态 game.js 在 dist 被按 assets 相对解析；改为基于 document.baseURI 的 URL，并用服务器子路径验证。
- 快照组件引用别名；捕获与恢复都深拷贝，直接重复恢复同一快照验证。
- 无网格父实体变换被丢弃；每实体统一变换节点。
- 祖先隐藏对 tracing 无效；按可见遍历提取几何。
- 只用整体 hash 或随机像素差异判断骨骼/相机可能假阳性；加入隔离形变、GPU 定向射线及相机方向断言。
- 测试夹具依赖源文件引号/排版；使用 AST 定位变更，避免格式化使负例没有实际修改。

- 远程 Windows CI 的跨盘符 source map 泄漏：规范化斜杠和大小写后映射 SDK 来源，未识别跨盘符来源明确报错；保留初次远程失败记录，修复后重新验收。

## 下一阶段的优先风险

生产材质/BSDF、光照采样和时空降噪；动态 BVH 与 GPU 模拟的数据共享；求解器之间的稳定双向耦合；完整 ECS/系统调度与资源生命周期；真实高质量资产管线；长期版本迁移和设备丢失恢复；完整 UI/音频以及更大场景流送。

下一阶段仍按总体计划 M1 基础契约推进，不在 M0 期间假装完成这些功能。具体源代码和测试需随实际提交重新校验；技术结论与用户需求不同，不可用本 ADR 静默缩减范围。
