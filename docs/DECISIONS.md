# 需求决策记录

日期：2026-11-04。状态：M0–M2 已发布，M3 开发中；本次范围变更新增 npm 开发分发、WebGL2 后端回退和面向 1.0 的性能策略。

本文件记录用户已经确认的产品要求。后续技术设计可以调整实现方法，不能自行删除目标、降低能力或将建议升级为使用限制。原对话中的纠正以本文件最终表述为准。

## 产品定位

`Pelican Engine`（鹈鹕游戏引擎）是面向 100% 外部 AI 开发的开源、代码优先、高质量游戏引擎，原名 threecat。人提出需求、约束和反馈；技术执行由外部 AI 完成。引擎研发者与游戏作者可以是不同用户。游戏运行时没有大模型或 AI 智能体。

选择路线 C：编译型 TypeScript SDK。引擎以 Three.js 的 WebGPU 能力为图形基础，完整封装底层；公开受控材质、后处理和 GPU 计算接口。游戏项目遵循公开接口开发，生态规范不等于防篡改。

## 已纠正的误解

1. “AI 友好”不是降低功能复杂度，而是降低不必要的使用歧义并增强观察、验证与修复能力。
2. “完整封装”不等于只提供预设。组件、系统、材质、后处理、GPU 计算、程序化内容都必须可表达新需求。
3. “不绕过引擎”是生态规范，不建设代码防篡改或违规产物封禁机制。
4. 开源引擎的研发修改，与游戏开发任务通过公开 SDK 开发，是两个职责，不冲突。
5. 游戏开发者可以自由获取和放置引擎；“仓库即产品”不要求游戏必须在仓库内。
6. Windows 是开发环境范围，不是玩家端拦截规则；固定机器是测试基准，不是准入条件。
7. 高质量光追/PT 是明确能力要求，不可用“光栅也可以很好看”替代。
8. 全首发范围很大，阶段性原型或局部可用版本不得冒称完整首发完成。
9. 资产生成服务是外部开发选择，引擎无需建立服务任务、账号、计费或模型管理平台。
10. 任何“游戏 AI”简称均弃用：只使用“引擎研发 AI”“游戏开发 AI”“NPC 行为系统”。

## 变更规则

实现方法、依赖版本和内部模块可以根据证据调整，记录原因与影响即可。删除正式首发能力、改变游戏开发边界或新增必要费用，需要回到用户需求决策，不能以“技术优化”名义自行处理。
