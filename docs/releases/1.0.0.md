# Pelican Engine 1.0.0

2026-11-08. Scope: D60 three-area integration. Standard stable version; no
milestone suffix and no `next` distribution channel. Main pushes publish the
repository version to npm `latest` using GitHub OIDC. The actual publication
outcome is the matching Actions publish result and GitHub Release, not this file.

## Included

- Interleaved native rigid/material integration on a shared substep clock;
  two-way reactions, shared WCSPH pressure/viscosity, moving-obstacle sweeps,
  bounded contact/constraint work and reconstruction transactions.
- Dynamic/kinematic/character chunk roots with parked velocities, gravity,
  sleep/character state, internal joints, model animation and wholly owned
  rope/cloth/soft-body/fluid solvers. Resources are released and rebuilt against
  fresh generations before animation/director evaluation.
- Multi-chain ground probes, bounded body adjustment, surface-aligned effectors,
  moving-support anchors, actual-displacement stride feedback, saved pose state
  and explicit cinematic ownership.
- Existing production 3D joints and native island-initialization patch remain
  integrated. Each native world/history candidate has separate JS/WASM memory;
  externally supplied native bytes are not deserialized into the live owner.

## Build Record

The final 1.0 source completed these allowed commands locally:

```sh
npm run typecheck
npm run api:index
npm run build
npm run distribution:pack
```

The API generator emitted 241 symbols. npm packaging produced
`pelican-engine-1.0.0.tgz`. Source/dist ZIPs and packaging manifests, when attached
to the Release, are inventories, not runtime or acceptance evidence. The static
dist is the existing default example game, not a demonstration of every D60 feature.

## Explicit Boundaries

No tests were written or run. No browser, GPU, numerical, performance, smoke,
installed-package, registry or runtime acceptance checks were run. Native first
removal, arbitrary-history recovery, old v3 compatibility, memory reclamation,
animation, coupling and stability remain unverified. Historical fixtures and
evidence retain their original identities and are not relabeled as current passes.

Incompatible cross-chunk joints, solver/stance dependencies, active navigation or
cinematic bindings, attached children, camera follow, visible world UI and spatial
voices must be detached before unloading. Prepared assets and terrain/navigation
grids remain shared services. This is not asynchronous asset streaming, arbitrary
gravity, ragdoll balance, volumetric destruction or proof that all historical
CAP/M1-M8 acceptance requirements are complete.
