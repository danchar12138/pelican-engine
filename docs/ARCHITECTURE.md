# 当前架构

本文描述当前实现，不以旧里程碑规划代替源码。SDK 类型、机器能力、命令协议和项目配置分别以各自源码为唯一契约；文档提供解释。

## 分发与工作区

`pelican-engine` 是唯一 npm 包，包含公开 SDK、编译器、运行时、渲染器及 `pelican` CLI。引擎贡献者使用此仓库；游戏作者只操作独立 npm 项目。构建不依赖 Git、引擎源码路径、AI 平台或账号。

编译器把 TypeScript 项目和资产转换为规范化 Scene IR、系统 JavaScript、资源及诊断；运行时消费 IR，浏览器渲染器消费受控的运行时资源。开发控制通道只在开发环境注册，默认生产输出不带控制服务。

## 内容构建

新建 npm 项目使用 `content: "typescript"`。普通 TypeScript 的循环、类、闭包、局部修改及浏览器兼容 npm 库均可参与场景构建；不再要求作者重写为自制的纯表达式语言，也不要求重复维护依赖白名单。SDK 工厂记录定义，输出仍走同一规范化、资源检查、系统调度和结构化诊断链路。

内容通过项目中的真实依赖打包后，在独立 Node 子进程构建；默认 10 秒截止时间，项目可设 `contentTimeoutMs` 为 100..120000。V8 heap 上限 512 MiB，数据限 200000 个序列化值、128 层、8 MiB 字符串。截止后终止子进程，不让内容循环占死编译宿主。这是可信构建代码的故障隔离，不是恶意代码沙箱，也不保证终止作者自行派生的其他进程。模块初始化必须能在 Node 和浏览器两端执行；浏览器对象放在运行系统内访问。

声明导出为有限的普通数据，系统 `run` 保留在游戏 JavaScript 中执行。内容应使用稳定 ID、确定性的构建数据；模块初始化在构建和浏览器加载时都会执行。不要把随机数、外部副作用或网络请求放进声明构造。资产通过正式资源接口输入并参与指纹。

没有 `content` 字段的旧项目继续使用 `static` 模式，维持不执行源码的语法和依赖边界。它是兼容与可选的确定性入口，不再作为所有 AI 作者的强制语言。

## 运行时与扩展

内容创作不是“只能使用引擎语法”：公开 API 描述需要由引擎管理的内容、调度与资源，其周围的 TypeScript 模块、生成器和第三方 npm 算法可自由组合。静态模式的限制只适用于选择该兼容模式的项目，不扩展为所有游戏开发禁令。

ECS、组件、同步系统、调度顺序、结构修改、事件、时间、输入、资源生命周期和保存恢复是基础。玩法可以用 TypeScript 模块和任意数据结构自行实现；需要参与引擎保存、检查与回放的数据应放公开组件或服务中，模块闭包状态不会自动成为存档。

背包、任务、对话、导航等是可选便利服务，不是游戏规则的必经路径。现阶段保留已有公开服务避免破坏 1.x 游戏。3D/2D 物理后端已拆成异步加载边；`services.physics3d` 可选 auto/required/disabled。auto 对未知用户系统保守准备，disabled 提供空世界查询并拒绝需要原生物理的声明或桥接调用。其余服务及渲染依赖仍有进一步拆分空间。

`runtime.create` 负责每实例异步初始化，构建只保留版本和调度元数据。作者资源通过 own/defer 逆序释放，状态通过完整的 snapshot/validateSnapshot/restore hooks 进入 Host 的恢复和回放事务。闭包仍不会自动序列化，作者负责完整覆盖状态。浏览器模块在 create 内动态 import；声明仍需能在 Node 构建。构建与浏览器声明指纹不一致时报告 TC_GAME_CONSTRUCTION_DRIFT。

外部能力通过 `createRuntimeAdapter` 接普通传输组件，显式声明端点 owned/borrowed，用 decode 验证后入有界队列，再由同步系统 drain。`own(resource, release)` 不改变第三方对象形状，listen 管理监听生命周期。端点所有权在同一 realm 的编译 SDK 副本间共享，避免场景候选模块重复拥有同一原生对象。异步数据、协议重同步和回放记录不被伪装成引擎已自动处理的内容。

标准模块 Worker 交给 Vite 构建，编译器额外收集其类型程序、模块依赖和分包产物；分包 URL 相对生成的 game.js，输出参与指纹检查。Worker 计算只通过消息传回作者代码，再更新既有受管缓冲／纹理，不直接取得引擎 ECS、物理或 GPU 内部对象。

受控图形计算、材质图、纹理和缓冲绑定是 GPU 扩展面。声明几何支持受管三角网格，材质支持常用 PBR 贴图输入。`defineRenderExtension` API v1 组合这些声明、系统帧阶段和版本化 runtime，资源进入现有诊断、所有权、清理和存档链路。普通 npm 算法不受 DSL 限制；任意 Three.js/TSL 插件及原始 GPU/物理对象仍没有通用接入契约。具体用法见 [INTEGRATIONS](npm/INTEGRATIONS.md)。

## 图形与物理

任务发现 `engineTasks` 与 guide 使用同一任务元数据，指向能力 ID、由公开 SDK 生成的方法索引与由源码生成的完整配方；未知查询返回带标签的候选，不维护第二份手写 API。

`defineGameRuntime` 是可选 TypeScript 组合辅助，系统声明一次、状态每实例创建并生成三段保存 hooks；未取消 JSON 校验、所有权或低级 runtime 接口。具体 Worker/WebSocket 适配复用通用消息桥，动态 JSON 使用流式字节预算、取消与超时。外部数据准备不直接修改世界。

dev 对声明一致的逻辑改动构造候选 Host，等待初始化后按完整检查点预检恢复，成功才替换；失败保留旧实例。声明、资源、版本和系统契约变化明确要求重启，不作任意 schema 迁移。自动刷新不再静默清掉状态。

渲染采用 Three.js WebGPURenderer，WebGPU 优先，内置 WebGL2 光栅回退。混合与路径追踪由 compute 软件 BVH 实现，并非硬件 RT。画质上限取决于算法、材质、动态支持和预算，不能把与基础光栅的一次对比推广为超过所有 Three.js 应用。

发光面采样使用 alias table，PDF 使用三角形索引查找；显式灯光的扫描范围不包含发光三角形表。静态发光元数据按不可变几何缓存。提取器对冻结数据保留私有 provenance，外部快照不能通过 freeze 绕过验证；动态几何打包和 GPU 更新使用缓存与对齐脏块，仍保留数值、引用和退化几何检查。

刚体由私有 Rapier 封装，布料、绳索、软体和流体有各自求解与交互边界。物理快照采用 ABI 绑定的原生检查点加有限回放尾部，保留旧 v3 快照兼容；候选恢复拥有独立 WASM 内存。这不是任意原生存档字节的安全沙箱。

## 后续架构优先级

1. 持续扩展 npm 作者的真实项目回归，减少静态子集成为新功能门槛的概率。
2. 对运行时服务、图形后端和加载成本做可测量的按需拆分，保持单包和公开类型稳定。
3. 在 API v1 受管渲染扩展上增加具体插件适配和必要的能力协商，保持显式生命周期与资源所有权；任意底层对象互通仍需独立设计。
4. 对动态追踪、复杂介质、降噪及模拟稳定性持续补充数值与图形证据；独立 Three.js 项目仍可通过自定义代码达到更高的专项效果。
