# M3 evidence preflight contract

`auditM3AcceptanceContract` consumes plain JSON and two explicit roots. The exported `M3_EVIDENCE_REQUIREMENTS` is the exhaustive descriptor list. Each descriptor must be passed, explicitly attested, marked `proof: "recorded"`, reference a nonempty regular file under the evidence root, carry its SHA-256, and identify the current source fingerprint. Categories and descriptors must each appear exactly once. Source is fingerprinted before and after the audit. `gpuTiming.method` is either `gpu-timestamp` or `unknown`; RAF is not GPU timing. No FPS threshold is imposed.

The default `post-publication` phase requires every descriptor, including registry parity. An explicit `pre-publication` phase permits only an absent `distribution/registry-parity` descriptor and reports it in `deferred`; if supplied it is still checked. This avoids requiring a newly published registry package before it can be published, without treating the later registry check as optional. A passed preflight in either phase is not formal acceptance or publication authorization. CI must verify the published bytes and installed package after publication; a failed post-publication check must be reported and investigated.

Evidence files are hashed as streams with a 128 MiB per-file cap; a file that grows beyond the cap during reading is rejected. Repeated references share a digest only within one audit, while each claimed hash is checked independently. Larger captures must be split or represented by a bounded manifest and independently validated by the eventual semantic verifier. This bound limits preflight memory use and is not a game asset or player restriction.

This is a structural preflight, not a verifier. Claims, identifiers, and hashes are supplied by the report author. An arbitrary file can be cited repeatedly; identity, independence, execution, content, sample quality and provenance are not established by this function. It returns `formalMilestoneAccepted: false` even on preflight success and writes no artifact. Source fingerprint scope follows `tools/source-fingerprint.ts`; it deliberately excludes evidence and docs. Concurrent adversarial filesystem modification is outside its integrity guarantees. Run on frozen, trusted local inputs and protect them throughout the eventual release operation.

The device and driver fields permit the literal `unknown` when privacy restrictions hide them; it is not evidence of hardware identity. The substantive verifier must establish the hardware/nonfallback claim independently and preserve unknown fields rather than inventing values or imposing player-side hardware restrictions.

## Outstanding execution and semantic hooks

1. Execute frozen-source full verification and zero-skip hardware tests, typecheck and public type tests; retain commands, logs, failures and source fingerprint before and after.
2. Validate static reference and dynamic public game scenes for all three modes, raw and processed images, scene/configuration, numeric error and causal assertions; verify material/texture/normal/deformation/topology/transparency/emission/light matrices, CPU reference, BSDF, illumination, hybrid contribution and diagnostics.
3. Execute sequential camera, animation, spawn/destroy, visibility, reload, snapshot, material, light and world changes; check geometry/version correspondence, refit/rebuild, stale tasks, reset, denoising, motion ghosting and occlusion.
4. Independently establish real WebGPU hardware, adapter, driver, browser, capabilities and no software/fallback; retain original samples for native dimensions, CPU/GPU timing or explicit GPU-timing unknown, memory/resources, refit/rebuild, resets and peaks, without silent quality reduction or fixed FPS gate.
5. Have an independent AI complete a new public-API material or rendering task, including traceable diagnosis and repair; establish independence and preserve the original workflow.
6. Test actual npm installation in a clean Windows directory without repository access, real GPU output, build and static deployment; validate ZIP and registry channel parity, offline after dependencies, MIT/third-party notices, package contents, single SDK/API, mismatch diagnostics, dist cold start and absence of development controls. Report registry credentials/publication state honestly.
7. Separately execute WebGL2 raster output, backend visibility, mode switching, unsupported compute/path/hybrid/denoising rejection and state/error semantics, no quality reduction, resource lifecycle and browser context loss/recovery. Execute WebGPU device loss/reconstruction and custom graphics lifecycle/diagnostics independently.
8. Implement a substantive formal verifier that executes or independently validates every hook and proof, ties each to the frozen source and records failures. Add negative and tamper tests for verifier and the future release profile. Integrate the M3 release profile only after these gates and real evidence exist; preflight success alone must never unlock release. Coordinate same-node commit/tag/push/Release/npm publication only after acceptance.

## Executable material-graph component

`npm run probe:m3 -- --checks material-graph-numeric` runs the fixed two-epoch WebGPU probe, preserves raw readback before assertions, compares the report with that readback and independently checks numeric semantics against the captured source fingerprint. Its output directory cannot be reused. This is one development component, not proof of adapter provenance, the full matrix or release acceptance.
