## 契约

- defineGame.computeBuffers 声明可在首帧前建立的受管理 CPU 缓冲；仍可运行时 createBuffer。MaterialInput.buffers 声明具名槽、GraphType、可选初始逻辑缓冲 ID 与精确 count。顶点图 readBuffer 只访问这些槽；不暴露 Three/GPU 对象，不扩散出第二套 SDK。
- render.buffers.bind/unbind/state 绑定的是受管理句柄，状态/快照存逻辑名称、类型与数量，不存原生资源或易失句柄。绑定类型/计数不符先拒绝。被渲染引用的缓冲不能 release，必须先解绑。writeBuffer 仍是显式 CPU 写，未结束任务时禁止写。
- 计算 run 可保留候选 GPU 输出；CPU 所有者完整校验结果后显式 commit 才发布对应 revision。取消/失败不改变已提交镜像或 GPU 输出。collect 在 flush 结束后回收非当前版本；同 tick 已捕获的旧版本在任务结束前保留，保持已有反馈语义。
- 渲染器从同一 executor 的已提交原生缓冲做 GPU→GPU 复制，更新 Three 自己持有的稳定 vec4 storage 属性，避免跨所有者释放原生对象。结果更新不把 CPU 镜像重新上传到渲染属性；初始值、显式 CPU 写、恢复/设备重建才允许重新上传检查点。
- 这不是零复制，也不是完全无读回：当前任务仍读回校验/CPU 镜像，供存档、BVH、动态 bounds 和查询。不能把这些成本隐藏成 GPU 全常驻。每条更新的真实 uploads/copies/revisions 应可诊断。
- 绑定状态与 compute 检查点做跨插件预检，完整成功后恢复。恢复后的缓冲代数身份变化，按逻辑 ID 重新取得资源；原句柄仍失效。GPU 缓冲的物理身份不会序列化。
- 本轮先接顶点槽。CPU 逐顶点 f32 镜像检查有限整数索引和范围，WebGL2 活跃存储槽明确不支持，不从 CPU 上传伪装 GPU storage；片元/后处理缓冲、任意 GPU 索引故障矩阵与纹理/任务依赖仍待后续完整实现。

当前小场景连续 9 次成功计算中仅有 1 次初始检查点上传，提交 revision 和 GPU 复制持续增加、渲染端结果上传为 0；队列结算后当前版本和 executor 缓冲保持各 1 个。越界失败及取消时提交/复制计数分别保持 9/10，旧几何不变。这些是受控夹具的因果/资源观测，不是任意负载的帧率保证。跨设备、跨缓存形态、动态改变全部槽维度以及 GPU 算术索引边界仍需完整矩阵。

额外限制：CPU 镜像和检查点仍逐任务读回；还没有纯 GPU 任务依赖链或 GPU-only 存档。当前不刷新旧 npm tarball/安装证据，也不执行全 M3 或 1080p。新接口的独立 AI 使用、渠道更新及正式 M3 verifier/profile 留到稳定候选，不能拿旧 1072 项基线当本轮全量通过。
