# M3 execution record

Only run from a fresh isolated candidate source workspace with exclusive GPU access: `npm run execute:m3 -- --isolated-candidate --hardware`. The flags are explicit operator confirmation; they do not establish isolation or exclusive access. The executor refuses existing `.pelican/npm/package` or `.pelican/npm/artifacts` before execution and again before packing. The underlying probes also generate other workspace outputs, including `dist`, so never run this in a workspace containing user data that must be preserved. The lock serializes this executor only in the same workspace. If interrupted, verify no executor is running before removing `.pelican/m3-execution/lock`.

The runner executes `npm test`, distribution tests, full `probe:m3` (which includes typecheck), `probe:backends`, package build/pack and installed-package smoke with `--gpu`, in order. It sets `PELICAN_BSDF_GPU`, `PELICAN_DENOISER_GPU`, `PELICAN_DIELECTRIC_GPU`, `PELICAN_ENVIRONMENT_GPU`, `PELICAN_MODEL_BROWSER`, and `PELICAN_TEXTURE_BROWSER` to `1`; it records the settings. A zero exit is not a zero-skip assertion: actual skip lines and the summary count are recorded, and missing or mismatched parsing is explicitly incomplete. Known skipped tests remain skipped; no test is altered.

Each stdout/stderr stream is retained up to 4 MiB, with first and last 2 MiB retained on overflow. Truncation and total bytes are recorded and prevent later steps; inspect both ends for failure diagnostics, since omitted middle output cannot be recovered. Exit codes, signals, timestamps, logs and pre/post source fingerprints are written under `.pelican/m3-execution/<run>/`. New artifacts are referenced in place, not copied. Probe directory hashes refer to the named report file; package file hashes refer to the file. Missing reports remain unhashed. Preserve the original output directories when transferring evidence.

This is an execution record, not a formal verifier or release gate. Independent AI execution and the complete independent image, quality, compatibility and resource matrices are not covered. Local package smoke is not registry verification; public registry verification remains post-publication. Nothing here authorizes release.
