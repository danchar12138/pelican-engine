# M2：完整游戏切片与真实资产管线

状态：待 M1 Release 交付后开始实现。本任务由用户已授权的 M1–M8 连续研发流程接续，不需要重新询问是否开发。

## 已确定交付目标

将只用公开 API 的第三人称关卡切片从启动做到通关与存档恢复：角色控制、跟随相机、碰撞、动画、一个敌人、交互、物品、任务、基础 UI、音效、保存和场景切换。不能把私人探针舞台当成用户游戏，也不把基础 UI/音频子集冒称 M6 完整体系。

M2 正式提供模型/纹理/动画/音频资源导入、校验、内容哈希与可解释构建，接入成熟运行库处理 GLB 和刚体。游戏定义仅通过 SDK，不把 Three、Rapier、DOM 或 GPU 对象公开。

## 候选写入分工

1. SDK/Schema/编译器：asset type 扩展、model/animation/body/controller/camera 配置，稳定运行命令与组件契约。先串行固化再分派。
2. 资产包：GLB 结构与资源完整性、PBR 纹理、骨骼/片段检查、打包与来源记录；下载生产素材不是必需流程。
3. 物理包：Rapier 3D 固定步封装、角色控制、碰撞查询和动态状态，资源释放与快照；2D 按最小契约接入，不宣称 M4 全功能。
4. 渲染包：GLTFLoader 私有接入、骨骼/Morph/动画混合、纹理色彩空间、灯光环境/阴影、相机、实例与资源作用域。保留后续路径追踪支持矩阵，不静默近似。
5. 游戏基础服务：输入映射、相机跟随、交互/存档、有限文本/面板与基础音频事件。服务可观察、可重放，不把必要行为写在浏览器测试壳里。
6. 样板与验收：公开 SDK 编写关卡游戏、自动试玩、失败路线、保存恢复、图像序列、根路径/子路径部署及独立 AI 新任务。

## M2 门禁

- 类型、编译、真实物理与资产失败分支、生命周期和快照回归。
- 带真实素材的可玩游戏，从进入、移动、交互、战斗或躲避、任务完成到通关；保存后冷启动恢复。
- 相机与碰撞无明显穿透、动画实际播放与切换、材质纹理可见，不只验证对象存在。
- 同一公开接口可新增实体/玩法/资产；独立 AI 不需修改引擎。
- 真实 WebGPU、画面检查、性能原始样本与限定负载，不以纯方块或静态截图宣称高质量资产能力完成。
- 完整 dist 静态发布，开发控制剔除，ZIP/外部路径与离线缓存流程成立。
- 更新对应 Release profile 和 verifier 后，按同一节点中文提交、推送、CI、标签、附件和摘要核对交付。
