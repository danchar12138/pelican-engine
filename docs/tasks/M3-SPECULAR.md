# M3 不透射物理材质高光颜色与强度

后续高光纹理增量见 [M3-SPECULAR-TEXTURES.md](M3-SPECULAR-TEXTURES.md)。下文是当时常数材质增量的历史记录，不能将其纹理限制或源码指纹当作当前状态。

透射材质的非默认高光仍未实现：当前表布局将相关槽复用于体积吸收，不能简单删除拒绝；介质全反射时也不能直接缩放 Fresnel 分支概率，否则会给不存在的折射分支分配概率。后续需要同时设计独立材质字段、彩色反射／透射与采样 PDF、全反射及 raster/path 差异，再用独立积分、硬件数值和三模式因果验证后开放。

落实已确认的统一物理材质及真实光追范围，不新增首发范围，也不代表 M3 已验收。开发增量已实现并通过下述受影响验证，尚未发布。

## 契约

- `defineMaterial` 提供 `specularIntensity` 和 `specularColor`，使用默认强度 1、默认白色；颜色接收 sRGB 十六进制或名称，线性值用于内部求值。公开接口不暴露 Three 或 GPU 对象。
- 不透射物理介质的正入射反射率、掠射 Fresnel、路径采样概率和 PDF 使用同一组强度与颜色；金属部分继续使用 baseColor 和金属掠射反射，不受介质高光颜色错误着色。默认值与此前 IOR 实现一致。
- 从受支持资产导入的物理材质也按同一规则处理。若与现有透射体积算法组合尚未实现，显式返回诊断，不静默改回默认或伪装真实透射。高光纹理和其他未实现扩展仍明确拒绝。
- 动态场景、缓存与快照保留材质值；非法范围和颜色明确报错。CPU 参考、光栅、hybrid、path 的定义一致；不得只修改视觉颜色而忽略实际采样密度与能量。

## 执行与验证

独立 worktree 负责 SDK、编译器、材质捕获、BSDF 及专属数值测试；主线准备只使用公开 API 的三模式因果场景，合并后集中类型检查并串行跑小型真实 GPU。按 D49 暂不重复完整 1080p、npm 安装或 M3 质量矩阵。

## 实际结果

- 受影响套件 296 项中 294 项通过、2 项 GPU opt-in 默认跳过；这两项分别在实际硬件上补跑并通过，BSDF 11/11、透射介质 10/10，计数与受影响套件重叠，不相加。额外分发相关定向 19 项通过，包含重复测试。集中类型检查通过。
- NVIDIA 非回退 WebGPU 的 72 组数值覆盖白色／彩色、强度 0／0.4／1、金属度 0／0.5／1、正入射／掠射及两种采样分支。GPU evaluate／PDF／方向／权重与 CPU 参考最大归一化误差约 `8.47e-7`；该验证范围是 BSDF 数值，不是完整场景物理真值。
- 320×240 公开游戏包含真实导入 GLB 的红色高光平面、相同 SDK 材质对照、零强度与绿色高光对照。raster/path/hybrid 中导入与 SDK 红色通道在对称视角的差异均小于 2 个显示字节，零强度保持黑色，绿色通道显著高于红／蓝。各模式输出及截图随证据保存；不是逐像素三模式质量等价证明。
- 资产检查仅支持 `KHR_materials_specular` 与 `KHR_materials_ior` 的常数材质因子；扩展纹理、透射扩展和其他未实现扩展仍明确拒绝。离线优化器注册这两个扩展并验证优化前后因子，防止静默丢失。
- `@gltf-transform/extensions` 4.5.1 已作为直接依赖明确列入仓库与 npm 构建元数据；原锁定树已有该 MIT 依赖及许可声明，没有增加新服务。随后已从当前源码打包，在引擎仓库外离线安装，使用安装包编译该 specular／GLB 游戏并由静态服务器真实出画面；证据 `evidence/m3/development/npm-current-1793895319798/`。全新 Windows OS、公开注册表及独立 AI 验收仍待稳定候选。

非默认高光与正 transmission 的组合、specular 纹理、清漆等高级物理材质和完整质量／故障矩阵仍未实现或未验收。渲染数据的 `attenuation` 存储在不透射与透射材质之间按类型复用；体积路径保持原有吸收值，不得把此内部打包细节变成游戏接口。
