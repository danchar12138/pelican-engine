# M5 正交网格导航增量

状态：开发增量，不是完整 M5 或 1.0 验收。游戏系统通过 `ctx.navigation` 创建和销毁带显式 owner 的二维正交网格、更新阻挡并请求路径；返回路径包含起终点。阻挡端点、不可达及搜索预算耗尽分别给出确定诊断；预算耗尽不伪装为不可达。默认预算为每次搜索 65,536 个不同格子，可由游戏按内存/CPU 需求显式提高。owner 是字符串分组，不自动绑定实体；游戏不获取寻路库对象。

`getGrid(id)` 返回包含当前阻挡格的独立网格描述，修改返回值不会修改运行时；`isBlocked(id, cell)` 查询单格的当前阻挡状态。两者遵循既有网格／坐标错误码、快照恢复和销毁语义。完整描述的复制成本随阻挡格数量增长，频繁的单格查询使用 `isBlocked`。

使用这两个查询的公开游戏在仓库源码与同机仓库外离线 npm 安装渠道分别通过真实 WebGPU 探针，两次 97 个阶段的 tick、游戏状态与变换一致；npm 项目还成功构建 `dist`。报告及截图保存在 `evidence/m5/development/navigation-inspection-1793931524152/`，源码指纹 `63b242a14dc988205f9cae56a230ac710e63bea22f2bafb5018b8b599f19713b`，开发候选包 SHA-256 `499069e654f07ea57f7d19e901ca57b09414658f6b5b44f496b6ab80be35faf9`。这是同一台 Windows 机器上的本地包验证，不是公开 registry、全新系统或完整 M5 验收。

实现以 `ngraph.path` 1.6.1 的 A* 为基础，按需构造搜索节点，不分配整张矩阵。验证覆盖 3×3 全部 128 个有效障碍布局与独立 BFS 最短路对照、4100 格长路径、百万格网格内的局部搜索、预算边界、1 万障碍更新和旧快照恢复。默认预算不是字节级内存保证；指定极大预算会增加设备内存和 CPU 消耗。该增量不是导航网格、连续世界、飞行、水下、群体或自动运动智能体。
