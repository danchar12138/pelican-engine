## 当前实现与复测入口

按 D49，日常先运行 `npm run probe:m3 -- --list` 发现检查 ID，再以 `--checks <逗号分隔ID>` 选择受影响项。例如 `npm run probe:m3 -- --checks image-history-lights,device-reconstruction` 只加必要的编译/服务前置，不跑 1080p、长时域或折射矩阵；报告列出 requested/automatic/omitted，未执行项不会记为通过。无参数的完整模式留给稳定冻结/发布前，子集成功不等于完整开发矩阵或正式 M3 通过。

- `surface.ts`：多材质组、UV/法线、蒙皮/Morph/实例数据及 CPU 材质参考；保留未知材质/变形的明确诊断。
- `texture-pixels.ts`：真实图片读取与内容生命周期缓存；surface cache 复用冻结纹理，版本和采样器变化触发失效。Fox/WaterBottle 浏览器采样与缓存复用已验证。
- `acceleration.ts`：拓扑重建、位置/形变 CPU refit、材质更新与射线查询；20 项测试包括 131,073 三角形和 3,000 条种子射线。不宣称 GPU BVH refit 或 BLAS/TLAS。
- `surface-gpu.ts`、`surface-shader.ts`：vec4 对齐数据布局、RGBA8/HDR 像素、sRGB 过滤、ORM/法线/alpha/side 的 WGSL 求值。
- `surface-ray-shader.ts`：GPU BVH 遍历与表面命中。1,062 条射线覆盖六状态及深度 128 的树，默认/近优先两布局与 CPU 对照；最大距离误差约 `7.6×10⁻⁷`。近优先原型仍不默认启用。
- `surface-motion.ts`、`motion-shader.ts`、`temporal-filter.ts`：上一帧变形位置、独立主命中运动通道、逐像素历史验证与邻域裁剪；与空间 à-trous 串联，静态连续累积不重复叠加历史。

完整硬件测试使用 `PELICAN_MODEL_BROWSER/PELICAN_BSDF_GPU/PELICAN_DENOISER_GPU/PELICAN_ENVIRONMENT_GPU/PELICAN_DIELECTRIC_GPU=1` 启用后执行 `npm test`，仅在冻结/全量回归需要时执行。1072 项零跳过属于上次分发冻结基线，不是受管理计算增量的全量结果。未请求硬件时相关 opt-in 会明确跳过，不能当作 GPU 证据。

`npm run probe:m3` 运行 16 项**开发探针**，新增运动数值、实际时域序列及原生 1080p 带时空降噪观测；其余覆盖环境、类型、材质/射线数值、编译、无人值守、图像/历史/灯光、空间参考、重建、折射、生产部署和源码稳定性。输出在 `.pelican/m3-probes/<run>/`，逐次记录源码指纹和失败尝试；已有通过记录归档到 `evidence/m3/development/`。折射接入前的历史记录 `1793826642017` 对应源码指纹 `242dc7b53c5dc1f47914abbdd17f9332fe4bfd731ba5d6f5454009a776f058d2` 和 840 项测试，不代表当前折射代码已通过该旧记录。所有开发报告明确 `formalMilestoneAccepted:false`，不生成正式 acceptance 或解锁发布 profile。

目前真实硬件证据包括：20 组表面求值（其中 8 组物理材质正/反面）；1,062 条射线的 initial/refit/rebuild/physical/empty/deep-128 六状态对照，分别检查默认线程化和内部近优先原型；双层 alpha 覆盖 16,384 条射线的前/后/透过概率约 `.503/.249/.248`，验证随机覆盖不是关联的同一个随机数。近优先原型无实测收益，默认不启用。折射子模块的原 773 包 GPU 失败已保留并修复，原门限下超限标量归零；现已连接公开材质和真实图像。`examples/refraction` 的 12 场景分别在 path/hybrid 实跑，24 组图像均无介质状态错误，解析 Beer 因子和有限点光源往返光程通过；完整探针另含介质设备重建检查。详见 `packages/renderer/VOLUME.md`。

`surface-tracer.ts`/`path-shader.ts` 已连接图像输出；hybrid 使用光栅首命中而非透明叠图，其阴影与二次光线使用同一材质。`surface-capture.ts` 对引擎已知标准 NodeMaterial 做明确转换，未知节点仍拒绝。`environment.ts` 从实际 PMREM 读取线性 HDR，`environment-importance.ts` 与 `emissive-lights.ts` 处理提案/MIS；`denoiser.ts` 为独立空间 à-trous；主链路先运行 `motion-shader.ts` 与 `temporal-filter.ts`，完整时域质量仍未验收。

设备重建专项主动销毁设备，分别在 path/hybrid/raster 中保留 tick、实体记录和模式，并验证新设备画面；这是受控故障验证，不代表所有驱动崩溃组合。绘制队列串行化修复了原生快速模式切换与异步管线初始化的竞态，其失败开发报告保留。

尚未完成的关键路径：完整物理材质/光照/动态/光栅厚度组合质量矩阵、复杂时域拖影/边界质量、完整自定义图形接口、资源和兼容故障矩阵，以及独立 AI 最终使用验收。高性能仍有实测缺口：原生 1920×1080、studio、5 次反弹、1 spp 的早期 GPU 约 635–708ms；线程化 BVH、any-hit、光源提案和 SAH 后完整探针约 287–354ms，仍明显不能视为实时高性能达标。不得以更低分辨率或减少能力代替该负载验收。

`evidence/m3/experiments/1793832880000/` 保留冻结源码 A-B-B-A 对照：不透明 BSDF 去重/编译期特化让 path/hybrid GPU 帧时中位数分别改善约 19%/18%，固定种子线性像素差在浮点舍入量级。近优先父指针遍历虽图像完全相同、深树射线通过，但未测得性能收益，因此默认仍用线程化遍历。旧记录 `1793831310272` 的 361–462ms 和全部失败记录保留，不覆盖或伪装成当前源码结果。

## 接口先行的实施顺序

1. 定义版本化渲染内容快照：几何局部顶点/索引/UV/法线/切线、实例变换、材质组、纹理与采样器身份、所有显式灯光和环境。渲染模式共享同一内容版本，游戏 SDK 不暴露 Three/TSL/GPU 对象。
2. 实现可测的纹理与 PBR 材质编码、实际表面采样和 BSDF。先建立与 CPU 参考及光栅材质输入的一致性断言，再加入采样策略；不将单张外观图当成物理正确性证明。
3. 区分实例变换更新、蒙皮/Morph 顶点更新与拓扑变化，验证 BLAS/TLAS 或等效分层结构的 refit/rebuild、生命周期、上传/同步成本及过期任务处理。不能每帧无条件重建全部 CPU BVH 后称为高性能动态结构。
4. 构建完整 PT 路径：直接/间接照明、反射/折射、发光与透明、重要性采样、累积和历史失效。移动相机、材质修改、灯光变化、动画、显隐、出生/销毁、世界修改均有明确重置规则。
5. 实现正式 hybrid：使用同一深度/法线/材质和运动数据，对已选光照项执行真实光线贡献并合成；逐项证明贡献因果。删除 M0 alpha 叠图原型的产品入口。
6. 实现可选时空降噪与去噪前/后输出，记录运动拖影、遮挡变化与资源重载行为。正确性、画质和性能分开验收。
7. 补齐设备丢失、资源重建、模式切换、自定义图形接口的生命周期与失败语义。明确当次适配器实际能力，不将测试显卡配置升级为玩家白名单。

## 必需验收

- 静态参考场景与动态公共游戏场景分别有 raster/hybrid/path 的原始图、处理后图、配置及误差/因果断言。
- 多材质组、真实 PBR 纹理、法线、蒙皮、Morph、实例变换、拓扑修改、透明/发光与多灯光逐项支持矩阵，缺项不能静默降级。
- 图像时序覆盖相机移动、动画、实体生成/销毁、显隐、重载和快照恢复；结构版本与可见几何一致。
- 原生输出尺寸、CPU/GPU 可用计时、内存/资源、refit/rebuild、历史重置与峰值事件有原始样本。GPU 不提供计时则明示未知，不以 RAF 代替。
- 新公开接口由独立 AI 使用，完成新的材质或渲染玩法任务，错误可定位/修复；dist 冷启动和开发控制剔除保持通过。
- 对应 verifier、source identity、release profile 和负例测试与能力一起实现，验收通过后同节点提交/推送/Release。
