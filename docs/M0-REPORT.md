# M0 里程碑报告

版本：`0.0.1-m0.0`。发布定位：**高风险技术原型预发布**，不是完整首发引擎。**10 个验收检查、165 项 CPU 测试及两条冻结源码的独立 AI 使用流程已通过。** 完整证据以 [acceptance.json](../evidence/m0/acceptance.json) 为准。

## 完成范围

四条主线已落地为可运行代码：

1. **编译**：TypeScript 类型检查、静态声明提取、组件/预制体/场景 IR、材质/计算图验证、普通玩法 JS、源位置诊断、资源依赖和内容哈希缓存。
2. **动态渲染**：Three.js WebGPU-only、光栅、简化光追合成、软件三角 BVH 路径追踪；相机、刚体、骨骼、Morph、模拟几何和拓扑修改的动态更新。
3. **交互模拟**：绳索/布料 XPBD、四面体软体、WCSPH 流体，与平移球体的代表性双向作用；Rapier 2D/3D WASM 候选的碰撞、射线、关节、快照与释放验证。
4. **外部 AI 闭环**：仓库指引、Windows 自动准备、创建游戏、结构化诊断、浏览器控制、截图、构建、普通服务器部署。独立 AI 验收单独记录，只有其冻结源码证据通过后才满足 M0 退出门禁。

附加验证包括有限世界分块、版本化修改、碰撞/导航数据一致性、取消与旧结果丢弃、跨区持久化、局部坐标精度，以及这些几何变更进入 BVH/PT 的链路。

## 图形实测的正确解读

环境为 Windows 11、Ryzen 9 9955HX、RTX 5070 Ti Laptop（nvidia-smi 12227 MiB）、Playwright Chromium 的有界面硬件 WebGPU。此机器不是覆盖所有主流显卡的测试集合。

当前基准使用原生 1920×1080 和约 520 个合成三角形，30 次固定步测量。静态采样、动态单样本以及两跳/五跳各自配置写在原始报告中。`fenceWallMs` 是每步等待 GPU 完成的串行墙钟时间，不是持续呈现帧率；`gpuComputeMs` 只统计 tracer compute，不含完整浏览器或光栅开销。

已取得的中间实测显示：光栅串行墙钟中位数约 5–6 ms，混合约 16–18 ms，五跳路径追踪约 27–33 ms；具体最终值以报告为准。这说明 **路径追踪目前未达到每帧 16.67 ms**，且测试内容远小于正式高质量游戏。不能宣称 1080p60 全模式目标已达成。此结果用于后续优化，不删除既定高质量目标。

## 明确未完成的内容

- 生产级 BSDF/MIS、多灯采样、透明/复杂材质、时空降噪、动态 BVH refit 和 GPU 常驻更新。
- 完整材质分解式混合渲染；当前只验证光栅与追踪图像合成。
- 任意 TypeScript 静态求值、完整 ECS 调度/资源体系、精细增量编译、保持任意状态的热替换。
- 高级模拟之间的通用双向耦合、旋转/摩擦/CCD、自碰撞和流体表面；当前四类参考模拟不是全功能物理引擎。
- 大规模连续世界、完整动态 NavMesh、完整 UI/输入法/音频/动画/过场以及全部玩法模块。
- 所有设备上的兼容和性能保证；玩家端依然按实际能力启动，不设白名单。

这些仍在完整首发目标内。M0 退出仅证明选型与关键链路有可重跑依据，不将 CAP 能力矩阵中的全部条目自动标为完成。

## 后续方向

进入 M1 时优先固化公开契约、实体/资源身份、时钟/调度/状态和编译边界，并保持现有原型作为回归基线。渲染和模拟后续优化不得引入游戏侧底层对象泄漏。各里程碑通过后按 [RELEASING.md](RELEASING.md) 自动提交、推送并创建对应 Release。
